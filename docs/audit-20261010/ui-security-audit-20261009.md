## Verified defects and smallest corrections

1. **Return Desk falsely diagnoses first visit as storage failure.** In `app/monitor.tsx`, `visitStatusLabel` and `baseline-note` resolve to MEMORY UNAVAILABLE / could not save when there is no baseline and loading is false. A first visit does not attempt a baseline write: `saveManualRefreshPreference` is called only for manual user-initiated refresh. Thus absent and unavailable are conflated. Keep a first-visit state saying no comparison saved yet and explain the manual-refresh action. Do not silently introduce automatic storage (privacy text explicitly promises control-triggered writes).

2. **Failed writes still produce saved semantics.** `lib/local-preferences.ts:saveManualRefreshPreference` catches a blocked-storage exception and returns undefined, also undefined on success. Its caller unconditionally sets `baselineSavedThisVisit=true` and installs `visitBaseline`; heading subsequently calls it a saved baseline, although reload loses it. Local execution of transpiled helper with `setItem` throwing confirmed no error/success distinction and null read. Return a discriminated write outcome, keep in-memory comparison on failure, and explicitly label it session-only. Watchlist and language writes similarly have no success signal, so avoid promising persistence when blocked.

3. **A deliberately empty watchlist does not survive reload.** `readWatchlistPreference` returns `[]` both for absent storage and stored `[]`; hydration only calls `setWatchlist` when length is nonzero. The default three selections reappear. Return nullable/typed read state distinguishing absence, invalid storage, blocked storage, and valid empty selection; restore valid `[]`.

4. **Chart x-axis misrepresents elapsed time and bridges missing intervals.** `LineChart` positions by observation index, not date. Local arithmetic reproduction with Jan 1, Jan 2, Oct 1 produces x=[5,50,95], versus elapsed-time x≈[5,5.33,95]. `NormalizedChart` does the same with the intersection of calendar months, compressing any missing months. Use actual UTC date/month offsets; explicitly indicate long gaps or separate line segments using source-frequency-aware expected gaps (do not treat weekends as provider failures). Update pointer selection to nearest date coordinate. No current gap warning is present.

5. **Base-100 axis label has incorrect vertical placement.** Normalized SVG computes the reference line with `y(100)`, while `.normal-y-scale` uses flex space-between for max, 100, min. Therefore 100 is always shown at the midpoint, which is wrong for asymmetric scales. Example min90/max310 gives y(100)=83.73%, but the label is approximately midpoint51%. Position the 100 label from the same scale function, or use the actual midpoint label and separately annotate the reference line. Current fixed pixel vertical padding also differs from SVG fractional plot bounds.

6. **Chart date validation checks only shape.** `prepareChartPoints` accepts `2026-99-99`; when it is the latest point, `cutoff.toISOString()` can throw. Even valid-looking Feb 30 normalizes silently. Upstream validation may normally prevent this, but the chart explicitly purports to sanitize. Use round-trip date validity, test malformed calendar dates, and safely reject points. This is a source-reproducible failure condition; not evidence that production currently contains it.

7. **Learning→monitor navigation loses selected language.** `app/learn/learn-home.tsx` has two links to `/` without `?lang=${lang}`. Its language toggle updates URL and state but does not persist the preference, unlike monitor. Open learn in EN with no saved preference, then return to monitor: monitor defaults ES. Preserve language in links and consistently implement explicit-choice preference saving, without passive writes. Course links already carry language correctly.

8. **Privacy route has incomplete language parity in its navigation shell.** It intentionally renders both full ES/EN bodies, but top heading, revision date, back aria-label, and initial clear-preference help are only Spanish; back link drops selected language. `ClearLocalPreferencesButton` defaults to `both`, but failure text has no English in that state. Preserve bilingual policy or choose language deliberately; make shell/helper states consistent. No missing English substantive privacy section found in reviewed body.

## Existing safeguards verified in source

- Upstream HTTPS host allowlist rejects credentials/nonstandard ports, explicit manual redirects reject 3xx before following, bounded response body and timeout exist. Inspected vinext image optimizer rejects external/protocol-relative URLs and normalizes backslashes before same-origin validation. No concrete SSRF path found in inspected code.
- D1 writes use bound placeholders and reads fixed SQL; no request-selected SQL identifiers or interpolation found. Shared macro data only, no account/file endpoint in reviewed code.
- Worker applies CSP, nosniff, DENY, referrer no-referrer, COOP/CORP, feature-denial headers to normal responses. CSP still permits inline scripts and styles; a hardening limitation, not demonstrated XSS. Worker and next.config.ts policies differ (self-hosting has broader worker/blob/form/referrer allowances); consolidate later with framework-compatible CSP testing. HSTS absent in application source; platform HSTS untested, so do not claim production absence.
- Local preference requests use same-origin fetch with credentials omitted and no referrer. Learning state is memory-only and privacy page says so. Existing source checks find no application tracker/cookie usage; this does not attest hosting telemetry.
- Chart keyboard selection/slider, labelled tabs, dialog focus trapping/Escape/return-focus, focus-visible styles, mobile breakpoints exist. Actual 320/360/390px overflow, contrast, touch targets, screen reader output, and dialog background interaction remain untested. Reduced-motion handling exists for two animated indicators and course transitions; it is not a full WCAG certification.
