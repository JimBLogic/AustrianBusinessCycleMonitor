# ABCM release 99 — bounded daily retries

30 October 2026. Scope: the existing public ABCM Site only.

An open monitor now makes at most three automatic generation attempts per daily
boundary per mounted tab. Attempts wait at least five minutes after completion
and respect Retry-After, shared-cache and upstream cooling deadlines. Success
stops retries. Cleanup aborts the request; re-renders preserve the same window's
budget and deadlines without allowing a late response to mutate a new window.
Automatic attempts do not create a user's comparison baseline or manual quota.
Reloading/remounting the whole monitor starts a new local budget; the server's
shared gate remains authoritative across tabs and clients.

Dependencies: Next 16.4.3; same-major overrides Undici 7.30.1 and Zod 4.6.6.
The full lockfile audit reports zero high/critical findings and four moderate
findings (@vercel/og, satori, vinext and fast-uri). No exploitability claim is
made. No major framework migration or workflow/security weakening is included.

Validation evidence is recorded in the release report and mirror PR. Regression
tests exercise failures, success, busy requests, long deadlines, cleanup, same
window remount and late responses crossing a boundary. A local self-host smoke
applied its migration only to disposable local D1, then was blocked by the
executor's uv_interface_addresses error; this is not a passing self-host check.
Managed preview serves the candidate and preserves explicit unavailable data.

No production schema migration, direct production D1 write, credential change,
audience change or BrangeCycle modification is part of this release. Version 98
is the archive-backed application rollback checkpoint. Application rollback
does not restore or alter data. Preserve the maintained GitHub automation.
